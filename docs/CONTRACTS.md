# Nexluna Contracts — v1.1.0

هذا الملف هو المرجع الرسمي لعقود الاستدعاء العامة في Nexluna. الحساب في Nexluna **حتمي دائمًا** من مصدر بيانات واحد (`data/units.json`)؛ لا يُضاف أو يُكرر أي عامل تحويل في أي طبقة أخرى (عقود، واجهة، مدونة، اختبار). الذكاء الاصطناعي اختياري ومقتصر على التفسير النصي، ولا يشارك في النتيجة العددية.

**Base URL:** `https://nexluna.netlify.app`
**اللغات:** العربية (`ar`, الافتراضية) والإنجليزية (`en`). الصفحات متبادلة عبر وسوم `hreflang`، والسجل الكامل في `sitemap.xml` (209 عناوين).

## 1. NexMCP — عقد أدوات الوكلاء (`assets/js/webmcp.js`)

واجهة استدعاء حتمية للوكلاء والعملاء الآليين (MCP/Web Tools style) معروضة من الصفحة نفسها بدون خادم. كل الأدوات تعرض `provenance` (مرجع المصدر لكل عامل تحويل) وتعيد أخطاءً مُصنّفة.

| الأداة | الوظيفة | المدخلات الأساسية |
|---|---|---|
| `NexMCP.convert` | تحويل قيمة بين وحدتين من نفس الفئة | `value`, `from`, `to` |
| `NexMCP.listUnits` | سرد وحدات فئة مع رموزها وبياناتها | `category` |
| `NexMCP.provenanceFor` | مرجع المصادر لكل وحدة وفئة | `category` |
| `NexMCP.explain_conversion` | تفسير نصي اختياري لخطوات التحويل (لا يغيّر الرقم) | `value`, `from`, `to`, `locale` |

**قاعدة الدقة:** ناتج `convert` يجب أن يطابق `data/units.json` بعد التقريب العشري القياسي. الاختبارات (`test_webmcp.js`, `test_webmcp_eval.js`) تحرس هذا العقد عبر الفئات الأربع عشرة (14/14 حالة في تقييم eval الأخير).

**خيار نظام وحدات البيانات:** لبيانات التخزين يدعم `convert` تحديد النظام: العشري (`KB, MB, GB` — مضاعف 1000) أو الثنائي (`KiB, MiB, GiB` — مضاعف 1024). الخيار واجهة فقط؛ المصدر canonical يحتفظ بكلا النظامين منفصلين.

## 2. واجهة التضمين (`embed.html` + `assets/js/embed.js`)

محوّل خفيف قابل للتضمين عبر iframe، مع ضبط عبر query string وبدون أي اعتماد خارجي.

| المعامل | الوظيفة | مثال |
|---|---|---|
| `category` | الفئة (اختياري، افتراضي الطول) | `length` |
| `from` / `to` | رموز الوحدات | `km` / `mi` |
| `v` | القيمة الابتدائية | `5` |
| `locale` | `ar` (افتراضي) أو `en` | `en` |

**عقد `postMessage`:**
- إرسال إلى النافذة: `{ type: "nx-convert", value, from, to }` — الرد: `{ type: "nx-converted", value, from, to, result, provenance }`.
- إرسال `{ type: "nx-init" }` — الرد بمعلومات الإصدار والlocale.
- الردود تحمل `provenance` دائمًا للمطابقة الآلية.

**CSP:** صفحة embed تحمل سياسة مستقلة تسمح `frame-ancestors` لأي أصل عند التضمين؛ الموقع الرئيسي يسمح بـ`frame-src` لخدمات الإعلانات فقط.

## 3. بنية i18n (`data/i18n/en.json` → `assets/js/locale.en.generated.js`)

طبقة النصوص منفصلة تمامًا عن منطق الحساب. الكتالوج يحتوي أسماء الوحدات (مفاتيحها رموز canonical من `units.json`) ونصوص الواجهة والبحث والشرح. إضافة لغة جديدة = ملف JSON واحد في `data/i18n/` + سطر في `data/locales.json` + مولد؛ لا يمس أي ملف حساب.

**قواعد الاتجاه:** `ar` → `dir="rtl" lang="ar"`، `en` → `dir="ltr" lang="en"`. `data-locale` على جذر المحوّل يحدد حزمة النصوص المحمّلة.

## 4. صفحات التحويل المولدة (`convert/{from}-to-{to}.html`)

163 صفحة زوجًا مولدة آليًا من `data/units.json` عبر `build_pairs.py` مع HowTo JSON-LD لكل زوج وItemList وBreadcrumbList لفهرس التحويلات. العناوين والأوصاف مستمدة من أسماء الوحدات canonical؛ لا تُكتب يدويًا.

## 5. نظام المحتوى (`data/content.json` + `build_blog.py`)

سجل canonical للمقالات التعليمية (9 مقالات حاليًا): slug، الفئة، العنوان والمقتطف بالعربية والإنجليزية، وأزواج الوحدات المرتبطة بمحوّلاتها. تُوثق المقالات بمصطلحات وحدات من مصدر canonical (فُحص كل زوج برمجيًا قبل النشر). المقالات تولّد `blog/{slug}.html` مع أسئلة شائعة FAQPage JSON-LD وروابط المحوّل المرتبط.

## 7. قيود صارمة

1. **لا تكرار لعوامل التحويل** — المصدر الوحيد `data/units.json`؛ كل الأرقام في الموقع والاختبارات والعقود تُولّد أو تُقرأ منه.
2. **الحتمية فوق كل شيء** — ناتج التحويل واحد بين جميع المسارات (واجهة، API، embed، اختبارات).
3. **الذكاء الاصطناعي تفسيري فقط** — طبقة الشرح اختياري ولا تؤثر على الأرقام.
4. **لا نشر خارجي من هذا المستودع محليًا** — النشر يتم يدويًا إلى الاستضافة عند قرار المالك.
